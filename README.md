# B站下载器（macOS）

原生 SwiftUI 应用 + 命令行工具 `bilidl`，用来下载哔哩哔哩视频。

- 默认下载 **1080P**（需扫码登录；未登录 B 站最多只给 480P）
- **列表下载**：多P、合集、系列、收藏夹、番剧/影视、UP 主空间、b23 短链、App 分享文案
- **弹幕**：通过分段接口拿全量弹幕，转成 ASS（自动分配轨道，不重叠）
  - 保存为同名 `.ass` 字幕（IINA / VLC / mpv 会自动加载），或
  - **烧录进视频并输出 60fps**：插帧到 60fps 后再渲染弹幕，滚动更顺滑
- 已存在的文件会跳过，同一个列表重复下载时只补缺的

## 依赖

macOS 14 或更高版本；从源码编译需要 Swift 6 工具链（Xcode 或 Command Line Tools）。

```bash
brew install ffmpeg
```

默认弹幕字体为「得意黑」，需自行安装 `SmileySans-Oblique.ttf` 到 `~/Library/Fonts/` 或 `/Library/Fonts/`；仓库不包含字体。也可以在设置中改用系统字体，例如 `Hiragino Sans GB`。

## 编译

```bash
./scripts/build-app.sh
```

输出 `build/B站下载器.app` 和 `build/bilidl`。可以把 App 拖进「应用程序」文件夹。

## 使用

1. 点右上角「扫码登录」，用哔哩哔哩 App 扫码
2. 粘贴链接回车（或 ⇧⌘V 直接粘贴剪贴板）
3. 列表会弹出勾选界面；单个视频直接开始下载

设置（⌘,）里可以改：保存位置、画质、视频编码、并发数、弹幕模式、60fps、编码器、弹幕字号/透明度/速度/显示区域/屏蔽等。

### 命令行

```bash
build/bilidl login                 # 终端里显示二维码扫码登录
build/bilidl BV1GJ411x7h7          # 下载单个视频（默认 1080P + 弹幕烧录 60fps）
build/bilidl --all "合集或收藏夹链接"   # 下载整个列表
build/bilidl -d ass -q 64 <链接>    # 720P + ASS 弹幕字幕，不重新编码
build/bilidl --list <链接>          # 只看解析结果
build/bilidl --help
```

加 `-v` 可在终端同时看到详细日志。

App 和命令行共用登录信息和设置（`~/Library/Application Support/BiliDownloader/`）。

## 说明

- 画质：1080P 需要登录；1080P60 / 1080P 高码率 / 4K 需要大会员。所选画质没有时自动降到不超过它的最高档。「有 60 帧版本时优先」开启后，大会员会直接拿 1080P60 原片。
- 60fps：非大会员的源视频一般是 25/30fps，烧录时会把画面帧复制到 60fps（画面本身不插值），弹幕按 60fps 渲染，看起来顺滑。
- 烧录需要重新编码，速度取决于弹幕密度（M1 Pro 实测，1080P → 60fps）：
  - 弹幕稀疏时瓶颈在编码，约 5~6 倍速；
  - 弹幕密集时瓶颈在 libass 渲染（单线程），单段只有 0.9 倍速，所以长视频会自动切成多段并行渲染，再无损拼接（4 段约 2.6 倍速）。段数可在设置里调整。
  - 「输出体积」档位（设置 → 弹幕，命令行 `-s`）。实测各档画质（VMAF）基本一致，差别在体积和编码耗时：

    | 档位 | 参数 | 密集弹幕体积 | 稀疏弹幕体积 | 编码 CPU |
    |---|---|---|---|---|
    | 速度优先 | x264 veryfast crf23 | 基准 | 基准 | 1x |
    | 均衡 | x264 faster crf25 | -21% | -8% | 1.4x |
    | **体积优先（软件编码默认档位）** | x264 medium crf26 | -32% | -20% | 2.1x |
    | 最小体积 | x265 fast crf26 | -34% | -40% | 4~5x |

    只想要最小体积又不在乎在别的播放器里显示，可以把弹幕模式改成「保存为 ASS 字幕」，完全不重新编码。
- 默认使用 Metal 绘制和 H.264 硬件编码。硬件编码持续低于 0.5 倍速时，看门狗会在约 20 秒后回退到软件编码；速度和体积取决于视频与设备。
- 重试：网络、CDN（含链接过期）、风控、ffmpeg 出错会自动重试（默认 2 次，间隔 5s/15s，设置里可改，命令行 `-r`）。视频不存在、无权限之类不会重试。重试和手动「重试」都会接着上次的进度：
  - 已下完的音视频直接跳过，没下完的断点续传；
  - 合并好的文件、生成好的弹幕字幕、已渲染完成的分段都会复用（一段渲染失败不影响其它段）；
  - App 退出时未完成的任务，下次打开会自动继续。
- libass 兼容模式应使用它能直接读取的字体；系统苹方字体可能逐字回退，影响渲染速度。
- UP 主空间列表接口风控很严，未登录时经常返回 412；可以改用合集或收藏夹链接。
- 高级弹幕（mode 7/8/9）不会渲染。

## 日志

`~/Library/Logs/BiliDownloader/日期.log`（App 菜单「文件 → 打开日志文件夹」⇧⌘L），保留 14 天。每个任务记录：

- 解析结果、接口返回码和耗时（风控 412/-352 会记 WARN）
- 可选清晰度、全部候选流、最终选中的流和 CDN 节点
- 音频/视频分别的大小、用时、速度、节点、重试和续传
- 弹幕总数、各类型数量、生成 ASS 时显示/过滤/因轨道放不下丢弃的数量
- 完整 ffmpeg 命令、编码器、并行段数、每 10% 的 fps 与倍速、每段用时、输出大小和码率、回退原因
- 一行汇总：`总用时 … ：解析 / 下载 / 合并 / 弹幕 / 渲染 / 收尾`

## 队列流水线

队列固定使用一个下载通道和一个合成通道：先下载第一项，第一项合成（合并音视频、弹幕烧录）时下载第二项。第二项下完后等待合成通道，不继续堆积下载；合成通道空闲后，第二项进入合成，同时下载第三项。不会同时合成两个视频，单个视频内部仍可分段并行渲染。失败重试和取消会释放通道，已完成部分仍可复用。App 与命令行使用相同调度规则；旧 `-j/--jobs` 参数仅兼容解析，不再改变通道数量。

## Metal GPU 弹幕绘制（实验）

默认使用 `Metal GPU`＋H.264 硬件编码、3 Mbps、自动分段。设置 → 弹幕 → 弹幕绘制，可切回 libass 兼容模式。Metal 路径只解析本程序生成的普通滚动/固定弹幕，支持得意黑、中英文数字、颜色、独立描边透明度；暂不支持 HDR、旋转视频、任意外部 ASS 特效或人物防挡。

- 字形用 CoreText 按 ASS 字号归一化后生成纹理；纹理创建一次，逐帧由 Metal 在单个 render pass 中完成 NV12→BT.709 RGB 转换、移动和预乘 alpha 混合。
- 选择 H.264/H.265 硬件编码时，通过 IOSurface 共享帧缓冲直接交给 AVAssetWriter/VideoToolbox；自动分段设置在该组合下使用单段，避免多个会话争抢媒体引擎。
- 选择 x264 时，GPU 帧仍需通过原始图像管道交给 ffmpeg，保留原 CRF 档位；这条路径不保证提速。
- 硬件目标码率可选自动或 3/5/8/12 Mbps。低码率会影响画质，不等价于软件 CRF 档位；自动码率体积通常较大。
- 重试指纹区分 libass/Metal，避免混用两种路径的已完成分段；取消和硬件编码回退保留原队列行为。

命令行示例：`bilidl --renderer metal -e h264 --hardware-kbps 3000 <链接>`。

离线基准工具：`swift build -c release --product bilibench`，然后运行 `bilibench input.mp4 timeline.ass output-dir metal h264 1 30 3000`。最后两个数字是片段时长（秒）和可选硬件码率（kbps）；基准不联网、不修改登录或应用设置。`scripts/gpu-benchmark.py` 对准备好的两段 30 秒素材依次运行多种组合，保存耗时、体积、进程 CPU 与整机 GPU 占用（整机 GPU 不能视为本进程独占数据）。

GPU 硬件路径缓存编码帧缓冲池，并最多保留三帧在途，让解码/GPU/编码重叠；每15秒记录 GPU 完成等待、编码背压和提交耗时。不要把低 CPU/GPU 占用直接解释为没用满硬件，专用编解码引擎不包含在这些百分比中。
